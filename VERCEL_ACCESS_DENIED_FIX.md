# DevDrop Vercel Access-Denied Fix

## What was wrong

The Vercel connection flow in the previous build did not send a CSRF state value, did not pass the returned `configurationId` through the frontend, and exchanged the Vercel installation code without the installation configuration context.

The previous flow also assumed that Vercel would not return the state supplied to the external installation URL. Current Vercel documentation explicitly documents `state` for the external installation flow and returns `code`, `teamId`, `configurationId`, `next`, and `state` to the configured redirect URL.

## What this build does

1. DevDrop creates a short-lived signed Vercel connection state bound to the logged-in DevDrop user.
2. The Connect Vercel URL includes `state` and the DevDrop frontend callback as `next`.
3. Vercel returns `code`, `teamId`, `configurationId`, and `state`.
4. DevDrop forwards those values to its frontend callback page.
5. The frontend calls the authenticated finish-connect endpoint.
6. The backend verifies that the signed state belongs to the currently logged-in DevDrop user.
7. The backend exchanges the one-time Vercel code and includes `configurationId` when supplied.
8. DevDrop stores the encrypted access token plus team/configuration/installation metadata.

## Required Vercel Integration Console settings

The Redirect URL in Vercel must exactly match:

`http://localhost:5000/api/deployments/providers/vercel/callback`

for local development, or the equivalent production backend URL.

Enable the scopes required by DevDrop:

- User: Read
- Team: Read
- Project: Read/Write
- Deployment: Read/Write
- Project Environment Variables: Read/Write
- Integration Configuration: Read/Write

Vercel documents these scopes and notes that missing `teamId` or insufficient scopes can cause 403 responses.

## If Vercel still says "Access denied" before returning to DevDrop

That error is being generated by Vercel's own installation UI, not by DevDrop's backend. The most common cause in this exact situation is a stale existing installation/configuration for the same Vercel team/account.

In Vercel:

1. Open Settings / Integrations.
2. Find the DevDrop community integration.
3. If it is already installed for `RIDEEMA SINGH's projects`, uninstall/remove that existing installation.
4. Save the Integration Console settings above.
5. Clear the Vercel site cookies or use an incognito window.
6. Restart DevDrop backend.
7. Click Connect Vercel again.
8. Select the personal account/team.
9. Select All Projects for the first test. After the connection works, project scoping can be tightened.
10. Continue.

If Vercel still shows Access denied after a clean reinstall, inspect the Vercel Integration Console for a pending/disabled scope change or account/team role restriction. DevDrop cannot override a permission decision made by Vercel's installation UI.
